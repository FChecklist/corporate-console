## 2. TOP PRIORITY: the sign-in code e-mail that never arrived (live, 20 Nov, TEST-ORG-1119, asked twice)

### How the mail is sent (code, base `ef84bc0`)
- Page: `public/screens/signin.js` -> `POST /auth/request` -> `functions/auth/[[path]].ts` -> `handleAuth` in `functions/_lib/auth-core.ts`.
- Order inside `handleAuth`: (1) the request must carry header `x-console: 1` and an `Origin` equal to `env.CONSOLE_ORIGIN` (line 149) or it is refused with 403 BEFORE anything is created; (2) address and consent checks; (3) limits: 60 an hour per office address, 8 an hour per e-mail address; (4) the code is written to the database; (5) `sendMail` (line 125) posts to Resend `https://api.resend.com/emails` with `Authorization: Bearer RESEND_API_KEY`; (6) any failure becomes `502 "The system could not send the e-mail. Please try again in a minute."` (line 169).
- Provider: **Resend**. Sender: `MAIL_FROM`, which is **not set** in `wrangler.toml` (the secrets list says it is), so the default `Corporate Games <console@corporatetambola.com>` is used. The report mail uses `hello@corporatetambola.com` instead (a different sender on the same domain). Plain text only, no reply-to, the subject carries the code.
- The mail service's answer is thrown away: no mail id kept, no log line, and the delivered/bounced events of Resend are wired only for REPORT mails (`report_watch`), never for sign-in mails. So a mail that Resend accepted but could not deliver leaves no trace in the console.

### What code alone CANNOT prove: check on the LIVE accounts (cheapest first)
1. **Browser, now:** open `console.corporatetambola.com`, press F12, Network, press "Send me a code" with a real address. Look at `POST /auth/request`: **403** = T-1; **502** = mail service refused (go to 4); **429** = limits; **200** = go to 2.
2. **Which address was typed for TEST-ORG-1119?** Ends `.invalid` = T-2: working as written, nothing was ever sent.
3. **Cloudflare, Pages project `corporate-console`, Settings, Variables and secrets, Production:** value of `CONSOLE_ORIGIN` (must be `https://console.corporatetambola.com`); `RESEND_API_KEY` is listed (name only, never read the value); `MAIL_FROM` (empty is fine). Custom domain `console.corporatetambola.com` attached to THIS project. (A Pages project with `wrangler.toml` uses the file's `[vars]`; the dashboard shows them read-only: the file wins.)
4. **Resend dashboard, Emails / Logs, 20 Nov:** no entry at the request times = the call never reached Resend (T-1, T-2, no key). An entry with status Delivered = look in spam; Bounced / Suppressed / Complained = the address is on Resend's suppression list. Also: domain `corporatetambola.com` is **Verified** (SPF and DKIM green) in the SAME Resend team that owns the key; the key is not restricted to another domain; the plan limit (daily and monthly) is not used up; the sender `console@corporatetambola.com` is allowed (the other mails of the suite use `hello@`).
5. **D1 console database:** `SELECT COUNT(*), MAX(sent_ms) FROM login_code;` and `SELECT k, n FROM rate WHERE k LIKE 'mail:%';`. A row with `sent_ms` near the request time means the request passed the origin check (so not T-1) and the send was tried. No row = refused earlier (T-1 or bad input).
6. After the fix is deployed, **Pages, Functions, Real-time logs**: a failed send now prints one line `sign-in mail not sent: mail <status> <resend error name>`.

### Fixes made (F-01 to F-05, section 4)
Settings carry the live address; `CONSOLE_ALT_ORIGINS` keeps the trial address working; a failed send puts the earlier code back and gives back the try; the mail call has a 10 second limit; the failure reason is logged (no address, no code); a test address is told so on the screen. **These need a redeploy to take effect** (BOSS owns that).
