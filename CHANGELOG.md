## 0.3.2 - 22 Nov 2026 (not deployed; the release time is stamped at deploy)
Branch `claude/console-0-3-0` (PR #7), on top of 0.3.1 (head 7135fec). Of the two independent audits of that head, one passed and one failed (one High, one Medium). This release fixes exactly those two. No money flag, no pay contract, no bridge, no pack, no function, no secret touched: `functions/`, `packages/`, `vendor/`, `contract/`, `config/`, `migrations/` and `docs/GAME_PAY_CONTRACT.md` are byte for byte as in 0.3.1. `PAY_VIA_MONEYPENNY` and `PAY_VIA_CONSOLE` stay OFF; no real payment was made.
In plain words: the sign-in link in the e-mail no longer breaks if the page reloads itself once, and the saved copy of the pages keeps working in Firefox and older Safari.
### Fixed: H1, an automatic reload killed the one-time sign-in code (`public/signin.js`, `public/core/offline.js`)
- **What went wrong.** `signin.js` took the one-time code (`?t=`) out of the address bar at once and kept it only in memory. For a returning visitor who still held an older offline worker (0.2.2 or 0.3.0), the clean-up that runs on every page (`page-consent.js` then `removeWorker`) loaded the page once more to free it. The reload had no code in its address, so the button sent an empty code and showed "That link has run out" (untrue).
- **Now.** (1) The code stays in the address until the sign-in is proven: after the button, the page posts the code once, then asks the server `GET /auth/me`; only when that says signed in does it remove the code from the address and go to `/`. If the server does not confirm (a browser that refuses the cookie), the page says so in plain words and keeps the address. A reload at any time before that finds the code again and uses it once. (2) `removeWorker` never reloads a page that holds a one-time code or typed input (`holdsOneTimeInput`: sign-in, pay-link and pay pages, the owner page, any address with `t=`); the worker is still removed and its cache deleted, and the page is free on its next load. (3) One press sends the code once (a second press while it runs does nothing). (4) `public/sw.js` never keeps `/signin` or any address that carries `t=` (it already skipped `/signin.html`; the plain pay-link page without a code stays kept as before).
- Why `/auth/me` and not a cookie read: the sign-in cookie is `HttpOnly`, so no script can read it, neither `document.cookie` nor `cookieStore`. The server's answer works in every browser.
### Fixed: M1, browsers without `cookieStore` (Firefox, older Safari) (`public/sw.js`)
- **What went wrong.** Where a worker cannot read the cookie it relied on a flag in memory set by the page's `go`. Browsers stop and restart workers all the time; a restarted worker started at "no", so it neither wrote nor served the saved pages (offline load failed although the copy was there). Its install step also copied the shell without waiting for `go`.
- **Now.** The feature check is explicit (`answer()` returns yes, no, or unknown). Where it is unknown: install copies nothing and the worker stays until the page says `go`; on `go` it leaves a marker cache `console-shell-grant` and copies the shell once; after a restart the marker tells it the page said yes, so the saved pages are served again. The marker lives under the `console-shell-` prefix, so every decline (the page's `removeWorker`, or the worker's own `stop`) deletes it with the rest, and a `stop` that arrives while `go` is running wins. A privacy signal (GPC, Do Not Track) still means no first. Where `cookieStore` works, nothing changes: the cookie decides.
### Tests

## 0.3.1 - 21 Nov 2026 (not deployed; the release time is stamped at deploy)
Branch `claude/console-0-3-0` (PR #7), on top of 0.3.0 (head 25dca5c), which both independent audits marked FAIL. This release fixes everything they found. No money flag, no pay contract, no bridge, no pack, no function, no secret touched: `functions/`, `packages/bridge/`, `packages/game-pack/`, `docs/GAME_PAY_CONTRACT.md`, `vendor/`, `contract/` and `config/` are byte for byte as in 0.3.0. The pay flag `PAY_VIA_MONEYPENNY` stays OFF.
In plain words: when you choose "Only what is needed", the saved copy of the console's pages is now really gone on every page, and nothing is put back afterwards.
### Fixed: the cookie decline (both audit Mediums)
- **M1, the old worker put the cache back after a decline.** An unregistered worker keeps holding the page that is open, and `public/sw.js` kept writing the cache for every later request. Now: (1) `public/sw.js` re-reads the cookie answer (`cookieStore`, where the browser has it) before every write and before it copies the shell; with a privacy signal or any answer except "Also remember your choices" it writes nothing, and on start it clears its cache and removes itself. Where the browser cannot show a worker the cookie, it writes only after the page has said `go`, never after `stop`, and a restarted worker starts from "no". (2) `public/core/offline.js` (`removeWorker`) tells every worker it can reach `stop` before removing the registration; the worker stops writing, clears its cache and answers `stopped`. (3) A page held by an older worker that does not answer (the 0.2.2 and 0.3.0 workers) is loaded once more, which frees it; it is done once only (a mark in the page's history state, nothing is stored) and only in that case. Then the console cache is deleted.
- **M2, a decline on the pay link page, the sign-in link page, the owner page and the 404 page left the worker and cache.** `public/core/page-consent.js` now follows the answer on every page (`cg-consent-changed`, and once on load to clear leftovers), through the same `syncOffline`. The words "Anything else was erased from this device" are now true on every page.
### Fixed: the cheap Lows
- Tapping Decline twice in My games opened two Yes / No questions; now one (`public/screens/mygames.js`, as on Home).
- "Next" for a game that is playing or has finished no longer says "your game runs at its time" (`stepSummary` in `public/core/steps.js`).
- A draft no longer claims a place it cannot know: "You may be at an earlier step: open the game to see how far you are" (banner) and "This draft may still be at an earlier step. Step 5 of 6 is ..." (game row).
- `X-Robots-Tag: noindex, nofollow` now also covers `/signin`, `/pay-link`, `/owner-funnel` and `/404`, the addresses without `.html` (`headersFile` in `build.mjs`).
- The public note of 0.3.0 and 0.3.1 says the double-press rule is for the console's own screens (the pack's setup screens are not part of it).
- `tools/serve-dist.mjs` (test server) serves a folder's index page for an address ending in "/", like Pages does.
- `once` and `lockAll` in `public/core/forms.js` are tested helpers for new screens; the screens guard themselves with a flag each (tests in `forms-idiot-proof.test.ts`). `docs/KNOWLEDGE.md` now says so instead of presenting them as what the screens use.
### Not changed on purpose (with the reason)
- `robots.txt` and `llms.txt` still name the private paths (`/auth/`, `/pay/`, `/report/`, `/stats/`, `/owner-funnel/`). These were audited in 0.2.2 and are locked by tests; the owner page still needs the owner key; every private page has `noindex` in its head and in the header. Whether to drop the names is a wording decision for the owner.

Anyone who answered "e-mail and layout" under the 0.2.2 wording (`cg_consent=v1.prefs`) now gets the saved copy of the pages under that same answer, without being asked again. This is still stricter than live 0.2.2, which set the worker up for everyone before any answer.

## 0.3.0 - 21 Nov 2026 (not deployed; the release time is stamped at deploy)

### Changed: cookie consent
- **No offline worker and no saved page copy before you answer.** Until now the console set up its offline worker (a saved copy of its own pages on your device) on the first visit, before the cookie question was answered. Now `public/core/offline.js` registers it only after the second answer, "Also remember your choices". Before an answer, after "Only what is needed", and with Global Privacy Control or Do Not Track, no worker is registered and no cached file exists; a worker or cache left by an earlier visit is removed at once. `public/core/boot.js` only follows the answer (the banner announces it with the event `cg-consent-changed`).
- Declining everything is one tap, the same size as accepting (unchanged). The words are warmer and say what each answer means, including the saved copy of the pages. "Cookie choices" in the footer changes your answer at any time.
- The owner page (`/owner-funnel/`) now starts the banner too: its footer had a "Cookie choices" link that opened nothing.
### Changed: step banner
- The banner says **"Step N of 6: name"** and **"Next: Step N+1 of 6: name"** in two lines above the six steps (`stepSummary` in `public/core/steps.js`). On the last step it says nothing more is left; for a cancelled or deleted game it claims nothing. Game rows in My games add "Next: ..." to their one-line step. "Start from an earlier game" shows the same banner.
### Changed: form fields, one press, confirm
- Every form field now has an example and its own error line right under it, in plain words, announced by screen readers and marked wrong (not by colour alone): sign-in e-mail, the agree box, the 6-digit code (a wrong shape is told without asking the server), the payee e-mail, the owner key and the two days of the owner page (`public/core/forms.js`, `signin.js`, `pay-link.*`, `owner-funnel/*`).

- Saying no to an invitation (Home and My games) asks Yes / No first; a failed answer on Home now says so instead of doing nothing.
### Changed: search and AI-search
- Signed-in screens ask search engines to stay away (`noindex,nofollow`) and have their own page title (`public/core/page-seo.js`); signed out, the public head comes back.
- `X-Robots-Tag: noindex, nofollow` headers on `/auth/`, `/pay/`, the sign-in link page, the pay link page, `/report/`, `/stats/`, the owner page and `/404.html` (in `build.mjs` `headersFile`; they cover static files; the function answers set their own headers, which this release does not touch).
- New `public/404.html`: says what happened in plain words and links to the console, the games, What's new and the help address (no dead end); built with `noindex`.
- Already in 0.2.2 and kept, now tested: unique title and description per page, canonical, Open Graph, JSON-LD Organization and WebSite, sitemap.xml (three public pages), robots.txt, llms.txt, no `<img>` without alt.
